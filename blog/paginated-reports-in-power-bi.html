Paginated Reports in Power BI: When to Use Them and How to Build One

Learn when to use paginated reports in Power BI and build a printable U.S. Letter invoice report in Power BI Report Builder, from dataset to PDF export.

NK
Nathalie
Consultant, Tycoon Clap
5 min read
Quick answer

Use paginated reports in Power BI for invoices, statements, and detailed exports that need consistent page breaks, repeating headers, or every row in a table. Build the .rdl file in Power BI Report Builder and use an interactive Power BI report for filtering, trends, and exploration.

Last updated November 2026

When paginated reports are worth building

Paginated reports give you control over the printed page. A service company can issue one invoice per customer and include line items, a subtotal, and a consistent footer. A distributor can print a packing list with repeating column headings. A controller can export every open invoice for a close review. These workflows benefit from predictable PDF or Excel output.

Reporting Services and Power BI share the RDL format for paginated reports. Teams familiar with SQL Server Reporting Services (SSRS) will recognize datasets, parameters, and grouping. If you already have an RDL inventory, use our SSRS to Power BI migration guide to assess compatibility and move existing reports.

Paginated reports vs. Power BI reports

NeedPaginated report (.rdl)Interactive Power BI report (.pbix)
Typical usePrint-ready invoices, statements, or long operational listsTrends, comparisons, and drilling into performance
Viewer controlsParameters such as invoice date and customerSlicers, cross-highlighting, and drill-through
LayoutPhysical page size, margins, page breaks, and repeating headersScreen-oriented report pages and visuals
Authoring toolPower BI Report BuilderPower BI Desktop

Many teams use both. The finance lead monitors overdue balances in an interactive report, then opens a paginated statement when a customer needs a PDF.

Power BI paginated reports tutorial: Build an invoice register

For this example, assume an approved SQL view or Power BI semantic model has one row per invoice line. It includes invoice number, date, customer ID, customer name, description, quantity, and line amount in USD. Include an invoice ID if displayed invoice numbers are only unique within each company or branch.

  1. Create a data source. Install Power BI Report Builder, create a blank report, and open the Report Data pane. Add a data source using an approved SQL connection or a Power BI semantic model. You need Build permission to author against the semantic model.
  2. Create the dataset and parameters. Add the invoice-line dataset and expose the fields used in the report. For SQL, use a parameterized date range such as InvoiceDate >= @StartDate AND InvoiceDate < DATEADD(day, 1, @EndDate) when the inputs are dates and the source stores timestamps. Map the dataset parameters to date-typed report parameters and add a customer filter if the owners need it.
  3. Lay out the table. Insert a table and group rows by unique invoice ID. Put invoice number, customer, and date in the group header. Put the item, quantity, and line amount in the detail row. Sum line amounts in the group footer for the invoice subtotal. Keep tax and shipping at their original grain so invoice-level charges are counted once.
  4. Set the page size and breaks. Choose U.S. Letter, 8.5 by 11 inches, and set 0.5-inch margins to leave 7.5 inches of usable body width. Keep the right edge of all body items within that limit. Add a page break between invoice groups if each invoice should start on a fresh page and configure column headers to repeat on later pages.
  5. Preview and reconcile. Run the report against one invoice, several invoices, and an empty period. Compare invoice counts and totals with the source. Use one multi-page invoice to verify headers and page breaks.
  6. Publish to a test workspace. Sign in from Report Builder, save the RDL, and publish it. Configure the service connection and an on-premises gateway if needed. Open the published report as a representative viewer and verify that the allowed rows and export work.

For the application workflow, follow Microsoft’s Report Builder tutorial.

Export to PDF and fix blank pages

Run the published report with your target parameters, then select PDF from the export menu. Open the generated file and review the first, middle, and last pages. The screen preview and PDF can paginate differently. If alternating pages are blank, check whether the body and margins together exceed the page width, including hidden whitespace or objects that extend past the right edge. For Excel consumers, test that the exported rows and totals remain useful when sorted or filtered.

See Microsoft’s paginated report page-view guidance.

What Power BI license do paginated reports need?

Report Builder is free to download, and users with a free license can publish to their own My Workspace. Publishing to another workspace requires Pro or Premium Per User (PPU) plus at least the Contributor role. On qualifying Fabric F64 or larger capacity, free users can view paginated reports when they have permission. PPU workspace consumers need PPU. Confirm the licensing for everyone receiving the report before rolling it out.

See Microsoft’s paginated report prerequisites and our Power BI pricing guide.

Frequently asked questions

Can I reuse an SSRS paginated report in Power BI?

You can migrate compatible SSRS RDL files as Power BI paginated reports. Review data sources, custom code, and other dependencies before publishing.

Can an interactive Power BI report also export to PDF?

Yes. Use an interactive report PDF to share its report pages. Use a paginated report when the PDF needs every detail row, repeated headers, or controlled page breaks.

Can a paginated report use an existing Power BI semantic model?

Yes. Connect Report Builder to a supported Power BI semantic model with Build permission and validate the result under the intended viewer permissions.
